01

Lists list

A train with numbered cars — you can add a car, remove a car, or change their order — and the order here actually matters.

The List is the most important data structure you'll use in Python. Simply put: an ordered collection of items that can hold any data type (numbers, strings, even lists inside lists). Its two most important properties:

  • Ordered: Every item has a fixed position (index) starting from zero.
  • Mutable: You can change, add, or remove items without creating a new list.
list_basics.py
fruits = ["apple", "mango", "banana"]

# Access by index (starts at 0)
print(fruits[0])        # apple
print(fruits[-1])       # banana -> negative means from the end

# Slicing: extract part of the list
print(fruits[0:2])     # ['apple', 'mango']
print(fruits[:2])      # same as above, start is optional
print(fruits[::-1])    # the list reversed

Why does the index start at zero?

Because the index isn't really "position" — it's the number of steps you walk from the first element. The first element requires zero steps to reach, so its index is 0. This idea is crucial when you start understanding slicing.

⚠️
The most common beginner trap — Reference, not Copy:
When you write b = a, you're not making a new copy — you're making b point to the same list that a points to. So any change in b will show up in a too.
reference_trap.py
a = [1, 2, 3]
b = a              # b points to the same list
b.append(4)
print(a)             # [1, 2, 3, 4]  -- changed too!

# The correct way if you want an independent copy:
c = a.copy()      # or list(a) or a[:]
c.append(99)
print(a)             # stays the same

02

Tuples tuple

A box sealed with wax: you can look inside, but you can never change what's in it.

A Tuple is exactly like a List in terms of order and index access, but the key difference: Immutable — once created, its contents cannot be changed at all. Why is that useful?

tuple_basics.py
point = (3, 7)
print(point[0])       # 3

point[0] = 10        # TypeError: 'tuple' object does not support item assignment

# A single-element tuple needs a comma!
one_item = (5,)      # actually a tuple
not_tuple = (5)      # just a regular number!

Why use a Tuple when we have Lists?

  • Safety: If you want to guarantee this data won't accidentally change anywhere in your code, use a Tuple.
  • Performance: Tuples are slightly faster than Lists to create and access, and use less memory.
  • Hashable: This is the most important point! A Tuple can be a key in a Dictionary or an element in a Set — a List cannot (you'll see why in the Dicts section).
unpacking.py
# Unpacking - the most common pro use of Tuple
name, age, city = ("Ali", 22, "Cairo")
print(name)    # Ali

# Swap values without a temp variable
x, y = 1, 2
x, y = y, x           # x=2, y=1 -- this is tuple packing/unpacking!

# Returning multiple values from a function -- actually returns a tuple
def min_max(nums):
    return min(nums), max(nums)

low, high = min_max([4, 1, 9, 2])
🎓
A fact only Advanced devs know: A Tuple can "contain" a mutable element like a List inside it — because Tuple immutability guarantees the references themselves don't change, not that everything inside is completely frozen. So t = ([1,2],) — you can do t[0].append(3) but you cannot do t[0] = something.

03

Dicts dict

A phone book: you don't look up a person by position — you look up by name and get their number instantly.

A Dictionary stores data as key-value pairs. There's no numeric index here — you reach a value directly through its key, which is much faster than searching through a List item by item.

dict_basics.py
student = {
    "name": "Sara",
    "grade": 3,
    "subjects": ["Math", "Science"]
}

print(student["name"])          # Sara
print(student.get("age", "?"))  # "?" -- get is safe, no Error

student["age"] = 16               # add a new key
del student["grade"]              # delete a key
⚠️
The difference between [] and .get(): If you use student["age"] when it doesn't exist, you'll get a KeyError and the program stops. But student.get("age", "undefined") returns a default value instead of crashing. Rule of thumb: use .get() when you're not sure the key exists.

Why must the key be Hashable?

Python converts every key into a unique number (hash) and stores it in an internal table, which makes key lookup very fast — roughly O(1) — instead of searching item by item like a List. The problem is that mutable objects like Lists can change, so their hash can change too, which would break the internal table. That's why a List can't be a key, but Tuple, String, and Number can (because they're immutable).

iteration.py
for key, value in student.items():
    print(f"{key}: {value}")

for key in student.keys():     # or for key in student: (same thing)
    print(key)

for value in student.values():
    print(value)
💡
From Python 3.7+: Dictionaries officially preserve insertion order. That doesn't mean they're "ordered" like a List by index — you still access by key only — but when you loop over one, items appear in the same order you added them.

04

Sets set

A bag of colored balls: no two balls share the same color, and there's no "first ball" or "second ball" — just presence or absence.

A Set is a collection of unique and unordered elements. What does that mean?

  • No duplicates — if you add an element that already exists, it won't be added again.
  • No index — you can't do my_set[0].
  • Lookup is very fast (similar to Dict) because it's built on the same hashing idea.
set_basics.py
nums = {1, 2, 2, 3, 3, 3}
print(nums)          # {1, 2, 3}  -- duplicates removed automatically

empty = set()      # must use set() -- because {} is an empty Dict, not a Set!

nums.add(4)
nums.discard(1)      # no Error if not found (unlike remove)

Operations that make Sets incredibly powerful

set_operations.py
a = {1, 2, 3, 4}
b = {3, 4, 5, 6}

print(a & b)   # Intersection -> {3, 4}
print(a | b)   # Union -> {1,2,3,4,5,6}
print(a - b)   # Difference -> {1, 2} (only in a)
print(a ^ b)   # Symmetric diff -> {1,2,5,6} (everything except shared)
🎓
Very common pro use case: Remove duplicates from a List quickly: unique = list(set(my_list)). Or find shared elements between two lists: common = set(list1) & set(list2). The performance difference is huge with large lists.
⚠️
You must know this: Set elements must be hashable too (exactly like Dict keys) — meaning you can't put a List inside a Set, but a Tuple is fine.
// SET — bag of unique balls

There's no order you can feel, and no duplicate copies of the same ball — the bag refuses to accept a color that's already in it.

Loops loops

The tool that lets you repeat anything without writing it 100 times by hand.

for loop — when you know what you're iterating over

for_loop.py
for fruit in ["apple", "mango"]:
    print(fruit)

# range(start, stop, step) -- stop is NOT included!
for i in range(0, 10, 2):
    print(i)          # 0 2 4 6 8

# enumerate -- get index and value together
for i, fruit in enumerate(["apple", "mango"]):
    print(i, fruit)   # 0 apple  /  1 mango

while loop — when you don't know how many times, but you know the condition

while_loop.py
balance = 100
while balance > 0:
    balance -= 30
    print(f"Balance: {balance}")

break, continue, and the hidden gem: for...else

control_flow.py
for n in range(10):
    if n == 5:
        break       # stops the entire loop immediately
    if n % 2 == 0:
        continue    # skips the rest and moves to the next item
    print(n)

# for...else -- else runs if the loop finishes normally without break
for n in [1, 3, 5]:
    if n % 2 == 0:
        break
else:
    print("No even number in the list")  # this will run here
💡
Advanced trick: Pros use for...else instead of a flag variable (like found = False) to know whether the loop found something or not.

Pro Tips & Tricks

The things that separate someone who writes Python from someone who truly understands Python.

1) List / Dict / Set Comprehension

Instead of writing a full loop to build a new List, Python gives you a shorter syntax that's also faster.

comprehensions.py
# The regular way
squares = []
for x in range(6):
    if x % 2 == 0:
        squares.append(x**2)

# List Comprehension -- same result in one line
squares = [x**2 for x in range(6) if x % 2 == 0]
# [0, 4, 16]

# Dict Comprehension
squared_map = {x: x**2 for x in range(4)}
# {0:0, 1:1, 2:4, 3:9}

# Set Comprehension
unique_lengths = {len(w) for w in ["hi", "cairo", "go"]}

2) zip() — combine multiple lists together

zip_trick.py
names = ["Ali", "Sara"]
ages = [22, 19]

for name, age in zip(names, ages):
    print(f"{name} -> {age}")

# Convert directly to a Dict
people = dict(zip(names, ages))

3) sorted() with key — smart sorting

sort_key.py
students = [{"name": "Ali", "grade": 85},
            {"name": "Sara", "grade": 92}]

# Sort by grade without writing a loop
ranked = sorted(students, key=lambda s: s["grade"], reverse=True)

4) The Walrus Operator :=

walrus.py
# Instead of computing the value twice
data = [1, 2, 3, 4, 5]
if (n := len(data)) > 3:
    print(f"The list has {n} items")  # n computed only once

5) collections — ready-made tools that save you a lot of code

collections_module.py
from collections import Counter, defaultdict

# Counter -- counts occurrences automatically
votes = ["A", "B", "A", "A", "C"]
print(Counter(votes))
# Counter({'A': 3, 'B': 1, 'C': 1})

# defaultdict -- Dict with automatic default value, prevents KeyError
groups = defaultdict(list)
groups["fruits"].append("apple")  # works without initializing [] first
🚀
Golden rule for performance: If you'll search for an element frequently, use a set or dict instead of a list. Searching a List takes longer as it grows (O(n)), while searching a Set/Dict is nearly constant (O(1)) thanks to hashing.
